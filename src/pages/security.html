In place today

The Co-Host Pro app currently runs privately to manage the holiday homes we look after in Dubai and our Airbnb homes in Gqeberha, South Africa. These controls are built into the software and in use now:

  • Passwords are hashed with bcrypt. They are never stored in plain text.
  • Signed sessions that expire. Logins use signed tokens that expire after 7 days.
  • Role-based access. Admin, manager, reservations, accountant, operations, cleaner and maintenance roles each see only what the job needs. For example, cleaners see their cleaning jobs, not finances.
  • Owner portal is read-only and scoped. Owners log in with a six-digit one-time code that expires after 15 minutes and allows a limited number of attempts. They can only see their own properties.
  • Activity log. Changes to bookings, income and expenses are recorded with who made them and the old and new values.
  • Secrets kept out of logs. Private iCal calendar links, passwords, tokens and keys are blanked out before anything is written to the activity log, and again when it's shown.
  • Locked financial history. Bookings and charges in a month whose owner statement was sent or paid can't be changed. Properties, owners and staff with history can't be deleted.
  • Nothing is sent unless switched on. Outgoing email and WhatsApp messages are off by default and need an explicit server setting to turn on.
  • Safe testing. Changes are checked with automated tests before release. Test copies run with channel sync switched off, and demo material (like the screenshots on this site) uses invented data only.

Commitments before handling Airbnb API data or opening to other businesses

Co-Host Pro does not connect to Airbnb's API today. Before it does, and before other businesses use Co-Host Pro, we will have the following in place. They match the minimum security requirements in Airbnb's public API Terms.

  • Multi-factor authentication for everyone who can access the system, its data or any API credentials. Two-step login is in development. No shared passwords.
  • HTTPS only for every connection, with modern cipher suites.
  • Managed hosting with encrypted storage, automatic daily backups and an off-site backup copy, plus regular restore tests. Data is hosted in {{hosting.dataRegion}}.
  • Least privilege. Access to production data and API credentials only for people whose job needs it.
  • Secure development. Testing against the OWASP Top 10, vulnerability scans at least every quarter, and security patches applied within 7 days (critical), 30 days (high), 90 days (medium) and 180 days (low).
  • Protected devices. Computers used to run or administer Co-Host Pro use full-disk encryption, password protection with multi-factor authentication and up-to-date anti-malware.
  • Vendor reviews. We review the security of the providers we rely on, such as hosting and email delivery.

Data from one host's account is used only for that host. We don't sell data, we don't use it for advertising, and we don't combine different hosts' data. For channel data specifically, see How we use Airbnb and other channel data.

Retention and deletion

  • We keep data only as long as it's needed to provide the service, or as long as the law requires. Examples are accounting records and Dubai guest records, which hosts must keep for set periods.
  • A customer can ask for an export of their data, or for it to be deleted, at any time.
  • When a customer leaves, or disconnects a channel, we delete the related data within 30 days, except records we must keep by law. Where we must keep them, we say which law.
  • Data received through Airbnb's API will be kept only while it's needed to deliver the host's service, and deleted as Airbnb's API Terms require.

Incidents

If we find or suspect a security incident, we will contain it, investigate it and tell affected customers without undue delay. Where a regulator or a channel partner must be told, we will tell them within the time they require. For Airbnb, that is within one hour for incidents involving Airbnb data or credentials and within 24 hours for others, as set out in Airbnb's API Terms.
